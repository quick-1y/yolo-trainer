<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> nginx -> api (multipart) | untrusted file bytes and client-chosen filenames cross here |
| api -> filesystem (data/projects) | the api writes files whose names must never come from the client |
| other web origin -> localhost api | any page open in the user's browser can attempt a cross-site multipart POST |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T2-01-01 | Tampering | process_image / upload route | high | mitigate | Full Pillow decode with `load()`; format allow-list via decoded `im.format`; stored extension from FORMAT_EXT, never from the filename; served with fixed `image/webp`; nginx server-level nosniff unchanged |
| T2-01-02 | Denial of Service | process_image (decompression bomb) | high | mitigate | Header `w*h` cap (`max_image_pixels`) and MIN_SIDE checked before any decode; JPEG `draft`; files processed sequentially per request |
| T2-01-03 | Tampering | storage path builders | high | mitigate | Paths built only from integer ids and a CHECK-constrained extension (D-18); `clean_filename` keeps display basename only; test uploads `../../evil.png` and asserts nothing lands outside data/projects/<pid>/ |
| T2-01-04 | Spoofing (CSRF) | POST /api/projects/{id}/images | high | mitigate | `require_xhr` dependency returns 403 without X-Requested-With; no CORS middleware, so the forced preflight fails cross-origin; tested in pytest and the smoke test |
| T2-01-05 | Tampering (stored XSS) | ImageTile / filename rendering | medium | mitigate | React text rendering and native `title` only, no HTML injection APIs; CSP from Phase 1 unchanged |
| T2-01-06 | Information Disclosure | immutable thumbnail caching | medium | mitigate | AUTOINCREMENT ids (never reused), so a cached URL can never show a different image |
| T2-01-07 | Tampering (integrity) | ingest pipeline | medium | mitigate | `UNIQUE(project_id, sha256)` race backstop; staged write + `os.replace`; rollback paths remove final files; FK failure on a deleted project returns 404 |
| T2-01-08 | Denial of Service | disk usage | medium | accept | Single-operator local tool; per-file cap (MAX_UPLOAD_MB) here, request cap via nginx; no disk quota — documented as an accepted risk in the README by Plan 02-04 |
| T2-01-SC | Tampering | pillow, python-multipart, react-virtuoso installs | high | mitigate | Approved in RESEARCH's Package Legitimacy Audit; registry repo re-checked before install; lockfiles committed; Docker installs only via `uv sync --frozen` / `npm ci` |
