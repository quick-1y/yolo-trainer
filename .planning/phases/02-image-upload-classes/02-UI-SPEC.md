# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: Images page (upload + virtualized grid + viewer + multi-delete), Classes page, and the small Phase 1 touch-ups (sidebar, overview, project card).
> Not greenfield: Mantine 9 dark theme, i18n (en/ru), sidebar shell and modal patterns from Phase 1 are reused. Everything below either reuses a P1 token/pattern or is listed under "Deviations from Phase 1".

Sources: CONTEXT.md D-01..D-19 (locked), RESEARCH.md Patterns 7/8 and Pitfalls 2/5, P1 D-01..D-11, installed `frontend/src` code (theme.ts, ProjectLayout.tsx, DeleteProjectModal.tsx, ProjectCard.tsx).

## Spacing Scale

Declared values (multiples of 4). Use numeric px props (`gap={8}`, `p={16}`) for this phase's new code.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tile item padding (two of them make the 8px grid gap), glyph gaps, badge inner gap |
| sm | 8px | Toolbar control gaps, tile caption padding, row inner gaps |
| md | 16px | Panel padding, page vertical rhythm, modal body gaps (Mantine `md` token = 16px, allowed) |
| lg | 24px | Section gaps (title row to toolbar), class row height padding pairs |
| xl | 32px | Sidebar/content gap (existing `gap="xl"`, Mantine `xl` token = 32px, allowed) |
| 2xl | 48px | Class row height, "Loading more" footer height, empty-state vertical padding |
| 3xl | 64px | Empty-state hero padding when the grid has zero images |

Do not use Mantine's `xs` (10px), `sm` (12px) or `lg` (20px) spacing tokens in new code (not on the scale). P1 files that already use them are not touched.

Exceptions (fixed component sizes, all multiples of 4 except borders):
- Grid tile: outer virtuoso item 184 x 208 (4px padding on each side), visible tile 176 x 200 = 176 x 176 square thumbnail + 24px caption strip.
- Viewer arrow `ActionIcon`: 40 x 40. Class color swatch: 24 x 24. Selection checkbox hit area: 32 x 32 wrapping the 20px Mantine checkbox. Sidebar width 200 (P1).
- 1px borders and 2px outlines/selection rings are not spacing.

## Typography

Exactly 4 sizes and 2 weights across all new Phase 2 UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`size="md"`) | 400 | 1.55 (Mantine `--mantine-line-height-md`; kept from P1 instead of inventing 1.5) |
| Label / secondary | 14px (`size="sm"`) | 400; 600 for emphasized labels (panel titles, badge counts) | 1.45 |
| Caption | 12px (`size="xs"`) | 400 | 1.4 (tile filename, badges, hex readout, index column) |
| Heading | 26px (`Title order={2}`) | 600 | 1.35 (Mantine h2 line-height) |

Weights: 400 (regular) and 600 (semibold) only. Emphasized body text (empty-state title, "Upload complete") is 16px at 600, not a new size.

Deviation from P1 (small, global): P1 Titles render at Mantine's default 700 and some cards at 500. To meet the two-weight rule, set `headings: { fontWeight: "600" }` in `frontend/src/theme.ts` (one line) and use `fw={600}` / `fw={400}` only; do not introduce 500 or 700 in new code.

Monospace is not used. The class index is plain 12px text with `font-variant-numeric: tabular-nums`.

## Color

Values are Mantine dark-scheme tokens already in effect (verified in `@mantine/core/styles.css`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#242424` (`--mantine-color-dark-7`, page body) | App background, AppShell main, gaps between tiles, grid canvas |
| Secondary (30%) | `#2E2E2E` (`--mantine-color-dark-6`) | Tiles, upload panel, class rows, modals, inputs, idle empty-state box |
| Accent (10%) | `#1971C2` (`--mantine-primary-color-filled`, blue-8 in dark) | See reserved list below |
| Destructive | `#E03131` (`--mantine-color-red-filled`, red-8 in dark) | Destructive actions only (see below) |

Accent reserved for:
1. Filled primary CTAs: "Upload images" (Images page header) and "Add class" (Classes page).
2. Selected tile: 2px inset ring and the checked-checkbox fill.
3. Drag-over state: dashed border and 12% tint on the `Dropzone.FullScreen` overlay.
4. Upload `Progress` bar fill.
5. Active sidebar `NavLink` (existing `variant="light"`) and keyboard focus rings (Mantine default).

Never for: hover states, tile borders, badges, links inside tables, class colors.

Destructive (red) reserved for: filled "Delete permanently" / "Delete class" confirm buttons, and the light-red "Delete" buttons that open those confirmations (selection bar, class row). Red is not used for decoration.

Status/feedback colors (separate from accent, used only in the upload summary and notifications): green (Badge `variant="light"`) = added / success toast; gray (`dark`) = already present; red (Badge `variant="light"`, and `Alert color="red"` as in P1) = rejected / error; yellow (Notification) = "upload already in progress" and cancelled.

Other rules:
- Tile border: 1px `--mantine-color-dark-4` (`#424242`); hover 1px `--mantine-color-dark-3` (`#696969`); selected 2px accent ring (replaces border). Skeleton/placeholder fill: `--mantine-color-dark-5` (`#3B3B3B`).
- Viewer stage background: `#141414` (`--mantine-color-dark-9`), the only place outside the 60/30/10 surfaces (media matte).
- Small informational text (12px and 14px) on `#242424` and `#2E2E2E` uses `--mantine-color-dark-1` (`#B8B8B8`, about 7.8:1 and 6.9:1). Do NOT use `c="dimmed"` (dark-2 `#828282`, about 4.0:1 and 3.5:1, below WCAG AA for small text) for new small text. P1 usages of `dimmed` are left as is.
- Class swatches always draw a 1px `rgba(255,255,255,0.24)` border, because some palette colors are under 3:1 against `#2E2E2E`.
- Class color palette (17 colors, `#RRGGBB` uppercase; same list on server `palette.py` and frontend `lib/classPalette.ts`, in this order): `#E6194B #3CB44B #FFE119 #4363D8 #F58231 #911EB4 #46F0F0 #F032E6 #BCF60C #FABEBE #008080 #E6BEFF #9A6324 #FFFAC8 #AAFFC3 #808000 #FFD8B1`. This prunes RESEARCH's 20-color suggestion by removing `#800000`, `#000075` and `#A9A9A9` (about 1.1 to 1.3:1 against the dark surfaces, or too close to UI grays). A drift between the two lists is cosmetic only (server assigns the default, client offers presets).

## Screen and Interaction Contract

### Sidebar and routes (ProjectLayout)
- Order: Overview, Images, Classes, Settings. Routes `/projects/:id/images` and `/projects/:id/classes`.
- Replace the two-section active logic (`isSettingsRoute`) with per-section matching: Overview is active only on the exact project path; others when the path starts with `/projects/:id/<to>`.
- While an upload runs, the Images `NavLink` shows a 16px `Loader` as `rightSection`.
- The content `Box` gets `min-width: 0` so the virtualized grid cannot overflow the flex row.

### Overview and project card (cheap counts, CONTEXT discretion)
- `ProjectCard`: add `Images: N` (14px, `dark-1`) under the relative-time line.
- Overview: below the description show `Images: N` and `Classes: N` (14px). When images are zero, replace the old hint with the existing hint plus a filled "Upload images" button linking to the Images route.

### Images page layout
- Page is a flex column with height `calc(100dvh - 92px)` (60px AppShell header + 2 x 16px main padding). Order top to bottom: title row, upload panel (only when active), toolbar, grid. The grid wrapper is `flex: 1; min-height: 320px`; `VirtuosoGrid` uses `style={{ height: "100%" }}` and its own scrollbar, so sidebar and toolbar never scroll away.
- Title row: `Title order=2` "Images" + count (14px, `dark-1`, `page.countFiltered` while a search is active), right-aligned `Group gap=8`: filled "Upload images" (inside `FileButton`), default-variant "Upload folder" (opens a hidden `<input type="file" webkitdirectory multiple>`). Both are disabled while an upload runs.
- Toolbar (row, gap 8): `TextInput` (width 320, debounced 300 ms, clearable via `CloseButton` right section, clears with Esc) and `SegmentedControl` (Newest first / By filename). Default sort is newest first (D-08). Changing search or sort clears the selection and scrolls the grid to top.
- When at least one tile is selected the toolbar is replaced by the selection bar: `Selected: N`, subtle "Clear selection", light-red "Delete". Esc clears the selection when the viewer is closed. There is no "select all" in this phase.

### Upload flow (D-01..D-05, RESEARCH Pattern 7)
- Entry points: file dialog, folder dialog, and drag and drop anywhere in the window (`Dropzone.FullScreen`). Drag-over shows a dashed 2px accent border, 12% accent tint overlay and the `dropOverlay` message as a `Title order=2`.
- Client pre-filter: non-image extensions and files over the size limit go straight to the rejected list with `reject.unsupported` / `reject.tooLarge`. `.DS_Store` and `Thumbs.db` are dropped by the library and not reported (documented exception to D-05). Limits come from `GET /api/config`.
- Batches of at most 10 files, concurrency 3. React state holds counters and the rejected list only, never per-file rows, and updates once per completed batch.
- While a second upload is attempted (drop or button), show a yellow notification `busy` and ignore the input.
- Upload state lives above the Images route (in `ProjectLayout`) so moving between sidebar sections does not cancel it. Leaving the project cancels the remaining batches; files already stored stay. A `beforeunload` guard is active while uploading.
- The grid refreshes once when the upload ends (`resetQueries`, scroll to top). It does not refresh per batch.
- Upload panel (`Paper`, `#2E2E2E`, 1px `dark-4` border, radius 8, padding 16, inserted with 16px below):
  - Running: `progress.title` (14px, 600), `Progress` bar (height 8, accent, not animated), `progress.counters` (12px, `dark-1`), subtle "Cancel" on the right. Bar exposes `aria-valuenow`.
  - Finished: `summary.done` (16px, 600) with light Badges for the nonzero counts (`summary.added` green, `summary.duplicates` gray, `summary.rejected` red), a `CloseButton` top-right, and `role="status"` announced once. If rejected is above zero, a `Collapse` toggled by `summary.showRejected` shows a `ScrollArea` (max-height 240) with at most 100 rows (filename 14px truncated with `title`, reason 14px `dark-1`), then `summary.more` when truncated, and a `CopyButton` "Copy list" that copies all rejected names and reasons as plain text.
  - Cancelled: `summary.cancelled` instead of `summary.done`, same badges.
  - Batch failure (network, non-JSON 413, 5xx): every file in the batch is added to rejected with `reject.requestFailed`; `summary.retryHint` shows under the badges. Re-uploading is safe because duplicates are skipped by hash.
  - The panel stays until dismissed or a new upload starts.

### Image grid (D-06..D-09, RESEARCH Pattern 8)
- `VirtuosoGrid` with flex-wrap list, `itemClassName` fixed 184 x 208, `increaseViewportBy={{ top: 400, bottom: 800 }}`, `computeItemKey` by image id, page size 100, `endReached` calls `fetchNextPage`. Do not use CSS `grid` auto-fill (RESEARCH A4).
- Tile (memoized): `Paper`-like box `#2E2E2E`, radius 8, 1px border as above. Thumbnail 176 x 176 `<img>` with `object-fit: cover`, `decoding="async"`, `alt=""` (the caption carries the name), background `dark-5` until loaded. Caption strip 24px: filename 12px `dark-1`, single line with ellipsis, native `title` tooltip (no Mantine Tooltip per tile).
- Reserved 24 x 24 slot in the tile's top-right corner for the Phase 3 annotation-status badge (empty in this phase, `pointer-events: none`).
- Selection (D-11): checkbox in the top-left, 32 x 32 hit area. Visible on tile hover, on focus-within, and always visible on every tile while at least one tile is selected. Click toggles; Shift-click selects the range from the last toggled tile within the loaded list. Clicking the tile body (not the checkbox) always opens the viewer (D-10).
- Keyboard: tiles are focusable (`role="button"`, `aria-label` = filename); Enter opens the viewer; the checkbox is a separate tab stop toggled with Space.
- Thumbnails load from `/api/projects/:id/images/:imageId/thumbnail` (immutable cache). `onError` swaps the image for a `dark-5` block with `tile.noPreview` (12px).

### Viewer modal (D-10)
- `Modal` centered, `size="min(1200px, 92vw)"`, header shows the filename (16px, 600, one line with ellipsis, full name in `title`) and Mantine's close button; body is a `#141414` stage, height `calc(100dvh - 200px)`, image `object-fit: contain`, loaded from the original `/file` route only for the open image.
- Arrow `ActionIcon`s (40 x 40, variant default, glyph `‹` `›`, `aria-label`) overlay the stage vertically centered, 16px from the edges. Keyboard: ← and → via `useHotkeys`, Esc closes. Prev is disabled on the first image; Next is disabled on the last image when no further page exists. Reaching the end of the loaded list with more pages triggers `fetchNextPage` and shows a `Loader` in place of the Next glyph.
- Footer row (14px, `dark-1`): `viewer.dimensions` · file size (`Intl.NumberFormat` unit style, MB) · `viewer.position`. Dimensions are the EXIF-corrected width and height from the API (D-17).
- Loading: centered `Loader` on the stage until the `<img>` fires `load`. Failure: `viewer.loadFailed` (16px, `dark-1`) centered; arrows keep working.
- In Phase 3 the tile click opens the annotation editor instead; this modal is then reused or removed there.

### Delete images modal (D-11)
- Opens from the selection bar. `Modal` title `delete.title`, body per Copywriting Contract, Cancel (default) and red filled confirm. Confirm shows a loading state; on success close, clear selection, remove deleted ids from cached pages, decrement the total, and show a green notification `delete.done`. On error the API message shows in a red `Alert` inside the modal and the modal stays open.

### Classes page (D-12..D-16)
- Order: `Title order=2` "Classes" + `page.count`; `page.indexHint` (14px, `dark-1`); add form row; class list.
- Add form: `TextInput` (label `add.label`, max 100 chars, Enter submits) + filled "Add class" button in one `Group gap=8`, aligned to the input's bottom. The server assigns the next unused palette color (D-15). Validation errors show under the input; on success the input clears and refocuses.
- List: one `Paper` (`#2E2E2E`, radius 8) with a header row (12px, `dark-1`: Index, Color, Name) and 48px rows separated by 1px `dark-4` borders. Row columns: index (width 48, 12px tabular numbers) · color swatch button (24 x 24, radius 4, 1px light border) · name (flex 1, 16px, ellipsis, `title`) · subtle compact "Rename" · light-red compact "Delete".
- Recolor: clicking the swatch opens a `Popover` with a `ColorPicker` (format hex, `swatches` = the palette, `swatchesPerRow` 6, `withPicker` on) and a 12px hex readout. PATCH fires on `onChangeEnd` only (not on every drag tick). The swatch updates optimistically; on failure it reverts and a red notification shows the API message.
- Rename: "Rename" swaps the name for an autofocused `TextInput` with the current value selected. Enter or blur saves (when non-empty and changed); Esc cancels. A 409 keeps the row in edit mode with the error shown until Esc. Renaming to a case-variant of its own name is valid.
- Delete: confirmation modal (Copywriting Contract). After deletion the list re-renders with the shifted indices and a green notification `delete.done`.
- The index shown is always the class's current position (0..N-1); no drag reorder in this phase (D-14).
- No pagination or virtualization for classes (expected under about 200); the page scrolls normally.

### Accessibility
- Glyph-only controls (`‹` `›` `×`, class swatch) carry `aria-label`s from the strings above. Modals trap focus and restore it to the trigger on close (Mantine default). Focus rings: Mantine default (2px accent, offset).
- The upload panel announces only start-of-summary (`role="status"`), not every batch. Progress bar has `aria-valuenow`/`aria-valuemax`.
- No custom animations are added; Mantine transitions only, honoring reduced motion.
- Body and secondary text meet 4.5:1 against both surfaces using the `dark-1` rule in Color.
