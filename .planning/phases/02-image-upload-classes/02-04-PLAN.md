Add, before `location /api/`, a regex location `location ~ ^/api/projects/[0-9]+/images/?$ { ... }` containing: `client_max_body_size ${MAX_UPLOAD_MB}m;`, `proxy_request_buffering off;`, and a full repeat of the proxy settings from `location /api/` (`proxy_pass http://api:8000;`, `proxy_http_version 1.1;`, `proxy_set_header Connection "";`, `proxy_set_header Host $host;`, `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`, `proxy_buffering off;`, `proxy_cache off;`, `proxy_read_timeout 3600s;`). nginx inherits `proxy_set_header` and response-header directives only when a level defines none of its own, so the new location must repeat every `proxy_set_header` and must define no response-header directive of its own (that would silently drop nosniff/CSP on upload responses). ## Trust Boundaries

| Boundary | Description |

| browser -> nginx | request bodies of attacker-chosen size reach the proxy first |
| .env -> containers | host configuration sets the body limit for nginx and the api |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T2-04-01 | Denial of Service | nginx body limits | high | mitigate | Large bodies allowed only on `^/api/projects/[0-9]+/images/?$`; server-level 1m kept for every other route; both asserted in the smoke test (413 on large upload and on a 1.5 MB JSON body) |
| T2-04-02 | Information Disclosure / Tampering | security headers on the new location | high | mitigate | The new location defines no response-header directive, so nosniff and CSP are inherited; region-scoped grep gate plus a smoke-test header check |
| T2-04-03 | Denial of Service | nginx startup with an unset variable | medium | mitigate | `ENV MAX_UPLOAD_MB=50` in the image and `${MAX_UPLOAD_MB:-50}` in compose, so the placeholder is always defined |
| T2-04-04 | Denial of Service | disk fill via many uploads | medium | accept | No quota in a single-operator local tool; documented in README (en + ru) as an accepted risk |
| T2-04-05 | Spoofing (CSRF) | upload route via proxy | high | mitigate | nginx forwards the X-Requested-With header unchanged; the api's `require_xhr` (Plan 01) still rejects cross-site multipart POSTs; recorded in 01-SECURITY.md T-09-03 |
</threat_model>
