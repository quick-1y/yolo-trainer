<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> api (JSON delete request) | the list of ids to delete is client-controlled |
| api -> filesystem | the delete removes user files from disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T2-11-01 | Tampering | POST /images/delete | high | mitigate | Rows selected by id AND project_id (cross-project ids ignored, tested); file paths built from those rows' integer ids and CHECK-constrained ext only |
| T2-11-02 | Denial of Service | huge id lists | low | mitigate | 1..1000 ids enforced by schema (422 otherwise); nginx 1 MiB body cap on this route |
| T2-11-03 | Spoofing (CSRF) | delete route | medium | mitigate | JSON content type forces a CORS preflight that fails (no CORS middleware); Host allow-list; client also sends X-Requested-With |
| T2-11-04 | Repudiation / accidental data loss | delete UI | medium | mitigate | Confirmation dialog required (prohibition test: no request before confirm); focus starts on Cancel |
| T2-11-05 | Information Disclosure | id reuse with immutable caches | medium | mitigate | AUTOINCREMENT verified by a delete-then-upload test |
</threat_model>
