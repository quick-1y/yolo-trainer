## Phase Goal

ROADMAP goal (verbatim): "A user can turn an annotated project into a trained model from the browser and download a `.pt` the downstream project can load, completing the upload → annotate → train → download loop". This plan keeps project deletion (PROJ-02, Phase 1) correct now that projects own runs and models (D-21). No user story is invented.

<objective>
Deleting a project removes everything it owns, including runs, run folders and models, is blocked while one of its runs is active or queued, tells the user beforehand what will go, and leaves no orphaned files after a crash.

Purpose: D-21 plus storage hygiene for the new `data/runs` and `data/models` trees (DEPL-03 data stays consistent; models of other projects keep working).
Output: guarded delete, file cleanup, orphan reconcile for runs/models, project counts in the UI, the extended delete dialog, tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> api (DELETE project) | a project id; the deletion races with the worker's claim |
| api startup -> filesystem | the orphan sweep deletes folders and files under data/runs and data/models |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T4-09-01 | Tampering (integrity) | project delete during training | high | mitigate | One guarded DELETE with NOT EXISTS active run; 409 tests incl. a run queued after the dialog opened (T4-05) |
| T4-09-02 | Tampering (mass deletion) | orphan sweep | high | mitigate | Canonical id names only, never follow links/junctions, empty-table safety valve, data/weights never scanned |
| T4-09-03 | Denial of Service (dangling base) | other projects' runs | low | mitigate | FK SET NULL on base_model_id, base_name kept as text; test |
| T4-09-04 | Spoofing (CSRF) | DELETE project | medium | mitigate | DELETE requires a CORS preflight that the api never grants (existing P1 stance) |
</threat_model>
