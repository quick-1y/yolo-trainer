## Phase Goal

ROADMAP goal (verbatim): "A user can turn an annotated project into a trained model from the browser and download a `.pt` the downstream project can load, completing the upload → annotate → train → download loop". This plan moves the Plan 04-01 path into the browser: the Training section, the run page and the start form. No user story is invented (run `/gsd-mvp-phase 4` for one).

<objective>
A user opens Training in a project, starts a run from a form pre-filled with standard Ultralytics defaults, watches it progress on its run page (and in the list) without refreshing, and downloads the `.pt` when it completes.

Purpose: TRAN-01 and MODL-04 in the browser on top of the proven worker pipeline; TRAN-04's "UI stays responsive, reopening shows the current status" through polling. The dataset summary, blockers, trained-model bases (Plan 04-08), the failed/interrupted run views and the settings card (Plan 04-07) expand this slice.
Output: options endpoint and verdict key on the backend; `api/training.ts`, `TrainingPage`, `RunStatusBadge`, `RunPage`, `RunMetrics`, `NewRunPage`, routes, sidebar entry, `training` i18n namespace, test stub helper and tests.
</objective>

| browser -> api (options GET, run POST) | form values and the device choice cross here |
| worker heartbeat file -> api | the api trusts a file written by the worker container on the shared volume |
| api JSON -> React | run names, base names, error text rendered in the UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T4-02-01 | Tampering (stored XSS) | TrainingPage, RunPage, NewRunPage | medium | mitigate | React text rendering only; `Code` for the usage snippet; no HTML injection APIs (grep gate on TrainingPage) (T4-08) |
| T4-02-02 | Elevation (arbitrary weights) | base select | high | mitigate | The client sends `{kind: "official", name}` only; the server re-checks the allow-list (Plan 04-01) (T4-01) |
| T4-02-03 | Denial of Service | form values | medium | mitigate | Client bounds mirror the server's RunCreate bounds; the server stays authoritative (T4-07) |
| T4-02-04 | Spoofing | heartbeat file | low | accept | Written only by the worker container on the operator's own volume; a stale or malformed file yields "no GPU", never an error |
| T4-02-05 | Spoofing (CSRF) | POST runs | high | mitigate | `apiRequest` sends JSON with X-Requested-With; the route keeps `require_xhr` (T4-06) |
| T4-02-06 | Information Disclosure | download link | low | accept | Single-operator, no-auth model; plain GET anchor to an id-derived path (T4-11) |
