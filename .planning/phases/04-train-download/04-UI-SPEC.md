# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: the project "Training" section (run list, New training form, run page), the dataset split controls (Images grid chip, bulk "Set split", "Split dataset" auto-split dialog, editor top bar split menu), the global active-run indicator (app header and editor top bar), and the run/model counts and active-run block in the delete-project dialog.
> Not greenfield: Mantine 9 dark theme, i18n (en/ru), spacing/typography/color tokens, modal and empty/error patterns from Phases 1-3 are reused unchanged. Everything below either reuses a P1-P3 token or is listed under "Deviations from Phases 1-3".

Sources: 04-CONTEXT.md D-01..D-21 (locked), 04-RESEARCH.md Patterns 1/2/4/5/8/9/10 and Pitfalls 15-18, 02-UI-SPEC.md and 03-UI-SPEC.md (tokens, copy conventions, tile geometry, top bar budget), 03-UI-REVIEW.md (spacing findings, see "Carried review findings"), installed `frontend/src` code (`theme.ts`, `AppLayout.tsx`, `ProjectLayout.tsx`, `ImageTile.tsx` + `.module.css`, `SelectionBar.tsx`, `StatusSummary.tsx`, `EditorTopBar.tsx`, `DeleteProjectModal.tsx`, `ClassesPage.tsx`).

No upstream design question was left open, so no questions were asked of the user. Choices made by this spec where CONTEXT leaves freedom (visual layout, status glyphs and colors, copy, split chip form, indicator form, auto-split dialog fields) are marked "default" and listed again in "Defaults to confirm" at the end.

## Spacing Scale

Declared values (multiples of 4). Use numeric px props (`gap={8}`, `p={16}`) as in P2/P3.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Glyph-to-text gap inside a button label (`▾` after text), pill inner padding, Progress to caption gap |
| sm | 8px | Gap between sibling controls (buttons, inputs, pills, menu triggers), row inner gaps, list row gap, form field label-to-hint gap |
| md | 16px | Panel padding, gap between form fields, gap between page sections inside a card, modal body gaps |
| lg | 24px | Gap between page-level blocks (title row, notes, form/summary columns, run page sections) |
| xl | 32px | Sidebar/content gap (existing `gap="xl"`) |
| 2xl | 48px | Run list row height, empty-state vertical padding |
| 3xl | 64px | Empty-state hero padding when the project has zero runs |

Do not use Mantine's `xs` (10px), `sm` (12px) or `lg` (20px) spacing tokens in new code (not on the scale), as in P2/P3.

Explicit composition rules (closes the 03-UI-REVIEW spacing ambiguities): the gap between sibling controls is always 8; a glyph that is part of a label is separated from its text by a 4px `marginInlineStart` span and never by a Mantine `leftSection`/`rightSection` (their built-in margin is off the scale); the gap between a field and its hint/error is Mantine's default (4px).

Exceptions (fixed component sizes, all multiples of 4 except borders):
- Run list: header row 32, data rows 48, row separators 1px `dark-4`.
- Dataset summary panel: 320 wide, padding 16, table rows 32.
- Auto-split dialog: `Modal size={480}`; ratio `NumberInput` 96 wide each.
- Progress bar 8 high. Stat tiles padding 16. Failure log `Code block` max-height 320 (internal scroll).
- Split pill on tile: 20 high, 4px inset (same box as the box-count pill). Indicator pill: 32 high.
- Editor top bar split trigger: 32 high, 104 wide below 1440px.
- 1px borders and 2px focus rings are not spacing.

## Typography

Exactly 4 sizes and 2 weights, the same set as P2. P3's editor chrome used 3 of them; the Training pages are regular pages and use the heading size again.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`size="md"`) | 400; 600 for run names in the list, epoch headline, empty-state titles | 1.55 (Mantine `--mantine-line-height-md`) |
| Label / secondary | 14px (`size="sm"`) | 400; 600 for panel titles, field-group titles, Alert titles, the ratio total when invalid | 1.45 |
| Caption | 12px (`size="xs"`) | 400 | 1.4 (table headers, hints under fields, split pill, indicator compact text, Badge text, file/size line) |
| Heading | 26px (`Title order={2}`) | 600 | 1.35 (page titles; also the four metric values on the run page) |

Weights: 400 and 600 only. Mantine's `--mantine-font-weight-medium` resolves to 600 in the installed 9.6.3 styles, so Input labels already meet the rule. Never write `fw={500}` or `fw={700}` in new code. The existing `fw={500}` in `SelectionBar.tsx` is changed to `fw={600}` because this phase edits that file.

Modal titles of the two new modals are set to 16px at 600 via `styles={{ title: { fontSize: 16, fontWeight: 600 } }}` (as P3) so no fifth size appears.

Monospace exception: the failure log uses Mantine `Code block` (monospace) at 12px / 1.4, because log lines must align. This is the only monospace text in the product. Inline code in the Python usage hint uses Mantine `Code` at 12px.

Numbers (epochs, counts, metrics, elapsed time, percentages) use `font-variant-numeric: tabular-nums`. Metric values are shown with three decimals via `Intl.NumberFormat(i18n.language, { minimumFractionDigits: 3, maximumFractionDigits: 3 })`. Elapsed time is `h:mm:ss`.

## Color

Values are Mantine dark-scheme tokens already in effect (verified in P2/P3 against `@mantine/core/styles.css`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#242424` (`--mantine-color-dark-7`) | Page body, gaps between rows, header background |
| Secondary (30%) | `#2E2E2E` (`--mantine-color-dark-6`) | Run list container, summary panel, status card, settings card, indicator pill, modal inner panels, inputs |
| Accent (10%) | `#1971C2` (`--mantine-primary-color-filled`, blue-8 in dark) | See reserved list below |
| Destructive | `#E03131` (`--mantine-color-red-filled`, red-8 in dark) | Destructive actions and error states only (see below) |

Accent reserved for:
1. The single filled primary CTA of each Training screen: "New training" (list), "Start training" (form), "Download .pt" (run page, completed runs only), "Apply split" (auto-split dialog). Never two filled CTAs on one screen.
2. The `Progress` bar fill of a running run (same as the P2 upload bar).
3. The active sidebar `NavLink` (existing `variant="light"`, now also "Training") and keyboard focus rings (Mantine default).

Never for: hover states, status badges, split pills, the indicator, links in rows, the quality verdict.

Destructive (red) reserved for: the red filled "Remove" confirm and its light-red opener "Remove from queue", the `failed` status Badge and the failure `Alert`, load-error `Alert`s, and error notifications. Red is not used for decoration.

Run status colors (separate from accent; `Badge variant="light" size="sm"`; the label text is always visible, so color is never the only signal):

| Status | Mantine color | Leading glyph | Label (en) |
|--------|---------------|---------------|------------|
| preparing | `gray` | `…` | Preparing |
| queued | `yellow` | `○` | In queue: {{position}} |
| running | `cyan` | 12px `Loader` | Epoch {{epoch}} of {{epochs}} (or "Running" before the first epoch) |
| completed | `green` | `✓` | Completed |
| failed | `red` | `×` | Failed |
| interrupted | `orange` | `!` | Interrupted |
| cancelled (reserved for Phase 5) | `gray` | `–` | Cancelled |

Quality verdict colors (`Badge variant="light" size="sm"`, with text): excellent `green`, good `teal`, fair `yellow`, poor `orange`.

Non-blocking warnings and blockers in the New training form use `Alert color="yellow" variant="light"`. Yellow is also the color of "queued". It is never used for destructive or error meaning.

Split pill on the grid tile is neutral: background `rgba(20, 20, 20, 0.8)`, text `--mantine-color-dark-1`, same as the P3 box-count pill. Split has no color coding on purpose (default): the text is the signal, and a third color system next to the image-status and run-status colors would add noise.

Small informational text (12px and 14px) uses `--mantine-color-dark-1` (`#B8B8B8`), never `c="dimmed"` (P2 rule).

## Copywriting Contract

All strings live in i18n: a new `training` namespace, plus additions to `images`, `project`. No hardcoded strings. Count-bearing strings use the "Label: {{count}}" form (P2/P3 convention; `locales.test.ts` compares flattened keys between en and ru, so no `_one/_few/_many` suffixes). Format numbers with `Intl.NumberFormat(i18n.language)`. API messages (409, 422, 5xx, run `error_message`) are shown as received, in English, even in the ru UI (P1 D-05). Russian terms: "запуск" = run, "выборка" = split, "обучение" = training (and the Train split), "валидация" = Valid split.

The Training `NavLink` is active on any `/projects/:id/training*` path (the existing per-section `startsWith` rule). ### Active run indicator (D-14)

One component, `ActiveRunIndicator`, with a `variant` prop. Data: `GET /training/active`, polled every 3000 ms, one request per page (shared query key). It renders nothing when no run is `running`. Queued or preparing runs do not show an indicator (default; they are visible in the list and on the run page).

- **Header form** (`AppLayout`, full): an `<a>` pill, 32 high, padding 0 16, radius 8, background `dark-6`, no border, text 14px/400 default text color. Content: 12px `Loader` (gray), 8px gap, label `indicator.full` (or `indicator.starting` while `epoch` is null), single line, ellipsis, max width 420, full text in `title`. Click navigates to `/projects/:projectId/training/:runId`. Not accent colored. `aria-live="off"`; the accessible name is the full label.
- **Editor form** (`EditorTopBar`, compact): placed immediately right of the flex spacer, before the split menu. At 1440px and wider: 32-high pill, padding 0 8, containing a 12px `Loader`, a 4px gap and `indicator.short` (12px, tabular), or the Loader alone while `epoch` is null. Below 1440px: icon-only 32 x 32 (16px `Loader`), same background. Both forms carry `aria-label` = the full label and a `Tooltip` (400 ms) with the full label. The editor form must not shift other top bar items (fixed width: 32 icon-only, 72 compact).
- **Editor click behavior:** a plain left click calls the editor's `goTo(runPath)` (save flush, then the "Changes could not be saved" dialog on failure), never a bare route change. Ctrl/Cmd/Shift/middle click falls through to the browser (new tab keeps the editor).
- Top bar fit requirement: at 1024px in ru the bar must still fit without clipping any fixed item; the filename shrinks first (existing rule, min 120px). If the sum of fixed items exceeds 992px, the split trigger loses its text prefix first (already the narrow form) and nothing else changes. Verified by the backstop row in UI Considerations.

`DeleteProjectModal` keeps its typed-name confirmation. After the existing warning text it shows, only when above zero, `project:delete.runs` and `project:delete.models` (each 14px, 600, same pattern as P3's `classes:delete.objects`). When the project has an active or queued run (`active_run_count > 0`), the modal shows `Alert color="yellow"` with `project:delete.blocked`, hides the typed-name input and disables the red confirm button; Cancel stays the way out. A 409 from the server (a run was queued after the dialog opened) shows the API message in the existing red `Alert`.

### Accessibility

- Glyph-only controls (`↓` download, the indicator's icon-only form) carry `aria-label`s from the strings above. Badges always carry text; glyphs are `aria-hidden`.
- Modals trap focus and restore it to the trigger (Mantine default). Focus rings: Mantine default (2px accent, offset).
- The run page announces only status changes through one polite live region; the progress bar exposes `aria-valuenow` and `aria-valuemax` with `aria-live="off"`. The indicator is `aria-live="off"`.
- The row link, the download button, split menu items, ratio inputs and the log toggle are all keyboard operable; `Menu` provides arrow-key navigation.
- Body and secondary text meet 4.5:1 against both surfaces using the `dark-1` rule in Color.
- No custom animations are added; Mantine transitions and `Loader` only, honoring reduced motion.

## Defaults to confirm (chosen by this spec, not locked by CONTEXT)

1. Indicator shows only for a `running` run (not for `queued` or `preparing`), and its editor form is compact (icon-only below 1440px).
2. Split chip is a neutral text pill at the tile's bottom-right and is hidden for unassigned images (no color per split).
3. Auto-split dialog has three integer ratio inputs (80/10/10), a live total, a counts preview, and no seed or reshuffle control; the "Split dataset" opener lives in the Images title row and in the New training summary panel.
4. Editor split control is a `Menu` button with no keyboard shortcut.
5. Batch is a `SegmentedControl` (Auto | Custom) and image size is a free multiple-of-32 number input rather than a preset list.
6. Run page has no resume or cancel buttons; `interrupted` offers only "New training"; `cancelled` is rendered but not yet produced.
7. Remove-from-queue asks for confirmation because it deletes the prepared dataset folder (hard delete, P1 D-10).
8. ru terminology: «Выборка» for split, «Обучение» / «Валидация» / «Тест» for the three splits, «Запуск» for run.
