# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: the full-screen Box Annotation Editor (route, top bar, tool bar, canvas, class panel, object list, save indicator, shortcut reference), plus the three small integrations in existing screens: status badge, box count and summary on the Images grid, and the "N objects" sentence in the delete-class dialog.
> Not greenfield: Mantine 9 dark theme, i18n (en/ru), spacing/typography/color tokens and modal patterns from Phases 1-2 are reused unchanged. Everything below either reuses a P1/P2 token or is listed under "Deviations from Phases 1-2".

Sources: 03-CONTEXT.md D-01..D-17 (locked), 03-RESEARCH.md Patterns 1/5/6/7/8 and Pitfalls 4/8/9/10/12, 02-UI-SPEC.md (tokens, copy conventions, tile geometry), installed `frontend/src` code (`theme.ts`, `ImageTile.module.css` badge slot, `AddClassForm.tsx`).

No upstream design question was left open, so no questions were asked of the user. Defaults chosen by this spec (shortcut map from RESEARCH, zoom limits, panel sizes, status colors, copy) are marked "default" where they are not locked by CONTEXT.

## Spacing Scale

Declared values (multiples of 4). Use numeric px props (`gap={8}`, `p={16}`) as in Phase 2.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Glyph gaps, chip inner padding, row inner vertical padding, ring offset |
| sm | 8px | Control gaps in the top bar, tool bar button gaps, row inner gaps, overlay inner padding |
| md | 16px | Panel padding, overlay offset from canvas edges, modal body gaps |
| lg | 24px | Fit-to-window margin around the image, section gap between class panel and object list |
| xl | 32px | Shortcut modal column gap |
| 2xl | 48px | Top bar height, tool bar width, canvas empty-state vertical padding |
| 3xl | 64px | Empty-state hero padding inside the right panel when both lists are empty |

Do not use Mantine's `xs` (10px), `sm` (12px) or `lg` (20px) spacing tokens in new code (not on the scale), as in P2.

Exceptions (fixed component sizes, all multiples of 4 except borders and canvas drawing units):
- Top bar 48 high. Tool bar 48 wide with 40 x 40 tool buttons. Right panel 320 wide.
- Class row and object row: 40 high. Top bar `ActionIcon` and row `ActionIcon`: 32 x 32. Class swatch in panels: 16 x 16, radius 4, 1px `rgba(255,255,255,0.24)` border (P2 rule). Status chip on grid tile: 24 x 24 (fills the reserved P2 badge slot).
- Zoom overlay pill: 32 high, 16px from the canvas bottom-left.
- Canvas drawing units (Konva): box stroke 2 screen px, selected anchors 10 px, crosshair 1 px, label chip height 16 screen px. These are in screen pixels via `strokeScaleEnabled={false}` and `1/scale` sizing, not CSS spacing.
- 1px borders and 2px rings are not spacing.

## Typography

Exactly 3 sizes and 2 weights are used by the editor. The P2 26px heading size is not used in the editor (the editor has no page title; the filename is a 16px label). Modal titles are set to 16px at 600 via `styles={{ title: { fontSize: 16, fontWeight: 600 } }}` on the two new modals so no fourth size appears.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / filename / modal title / panel empty-state title | 16px (`size="md"`) | 400; 600 for the filename, modal titles and empty-state titles | 1.55 (Mantine `--mantine-line-height-md`, as P2) |
| Label / secondary | 14px (`size="sm"`) | 400; 600 for panel section titles ("Classes", "Objects: N") and the filled/active top bar button label | 1.45 |
| Caption | 12px (`size="xs"`) | 400 | 1.4 (save indicator text, "N of M" counter, zoom percent, object ordinal, per-class object count, canvas label chips, status Badge, Kbd, hints) |

Weights: 400 (regular) and 600 (semibold) only. No 500 or 700. Konva `Text` for box labels uses `fontStyle: "normal"` (400); legibility comes from the colored label chip, not from weight.

Monospace is not used. Numbers in counters, ordinals and zoom percent use `font-variant-numeric: tabular-nums`.

## Color

Values are Mantine dark-scheme tokens already in effect (verified in P2 against `@mantine/core/styles.css`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#141414` (`--mantine-color-dark-9`) | Canvas matte behind the image (the canvas is about three quarters of the viewport). Same matte color P2 uses for the viewer stage |
| Secondary (30%) | `#242424` (`--mantine-color-dark-7`) | Top bar, tool bar, right panel (class list and object list backgrounds), canvas overlay pills. 1px `--mantine-color-dark-4` (`#424242`) separators between chrome regions |
| Elevated (inside secondary) | `#2E2E2E` (`--mantine-color-dark-6`) | Row hover and selected row background, inputs, modals, toasts |
| Accent (10%) | `#1971C2` (`--mantine-primary-color-filled`, blue-8 in dark) | See reserved list below |
| Destructive | `#E03131` (`--mantine-color-red-filled`, red-8 in dark) | Destructive actions and error states only (see below) |

Accent reserved for:
1. The active tool button in the tool bar (filled accent, 40 x 40, radius 8).
2. The 2px inset ring on the active-class row in the class panel and on the selected row in the object list (a row never uses accent as a fill).
3. Filled primary buttons: "Annotate next" (Images grid), "Retry" (unsaved-changes dialog) and the existing "Add class" (P2, reused in the inline form).
4. Keyboard focus rings (Mantine default: 2px accent, offset).

Never for: hover states, status badges, save indicator, box strokes, class colors, selection handles, links.

Destructive (red) reserved for: the "×" delete-object button (`color="red" variant="subtle"`), the light-red "Leave anyway" button, the existing red "Delete class" confirm (P2), error `Alert`s, and the Error state of the save indicator.

Canvas drawing colors (the only colors outside the token table; all derive from the user's class color `C`):

| Element | Value |
|---------|-------|
| Box stroke | `C`, 2 screen px (3 px while hovered) |
| Box fill | `C` at 18% alpha; 30% alpha while hovered or selected |
| Label chip | background `C` at 100%, text `#000000` when the class color's relative luminance is above 0.5, otherwise `#FFFFFF` (the 17-color palette from P2 is mostly bright, so black text is the common case) |
| Draft box (while dragging) | stroke `C` of the active class, dashed `[6, 4]` screen px, 2 px, fill `C` at 18% |
| Selected box | stroke `C` 2 px + Transformer: 1px `#FFFFFF` border, 8 square anchors, 10 x 10 px, fill `#FFFFFF`, stroke `#141414` 1px; no rotation anchor |
| Crosshair guides (box tool) | 1px lines, `rgba(255,255,255,0.7)` with a `rgba(0,0,0,0.6)` 2px blur shadow so they read on both light and dark images; span the whole canvas viewport (not just the image), follow the pointer, hidden when the pointer leaves the canvas or while panning |
| Hidden box (eye toggled off) | not drawn, not hit-testable; its row stays in the list at 50% opacity |

Status colors (separate from accent; Mantine `Badge`/`ThemeIcon` `variant="light"`):

| Status | Mantine color | Glyph (never color alone) | Used in |
|--------|---------------|---------------------------|---------|
| unannotated | `gray` (dark) | `○` | Tile chip, top bar badge |
| annotated | `cyan` | `●` | Tile chip, top bar badge |
| reviewed | `green` | `✓` | Tile chip, top bar badge |
| background | `grape` | `∅` | Tile chip, top bar badge |

Save indicator colors: Saved = 8px green dot (`--mantine-color-green-6`) + 12px text `--mantine-color-dark-1`; Saving = 12px `Loader` (gray) + the same text; Error = 8px red dot (`--mantine-color-red-6`) + 12px text `--mantine-color-red-4`.

Small informational text (12px and 14px) uses `--mantine-color-dark-1` (`#B8B8B8`), never `c="dimmed"` (P2 rule).

## Screen and Interaction Contract

### Route and shell (D-01, D-03)
- Route `/projects/:projectId/annotate/:imageId?sort=&q=` is a sibling of the `AppLayout` route, lazy-loaded (`React.lazy` + `Suspense` with a centered 32px `Loader` on `#141414`). No project sidebar and no app header: the editor owns the full viewport.
- Frame: CSS grid, columns `48px 1fr 320px`, rows `48px 1fr`. Top bar spans all columns; tool bar left; canvas center; right panel right.
- Back (the `← Images` top bar button; Esc is reserved for deselect/cancel and does not leave the editor) navigates to `/projects/:projectId/images?sort=&q=` with the same params (D-03). Unknown project or image id renders the existing not-found view with `notFound.*` strings.
- All in-editor navigation (prev, next, N, Back, top bar) goes through one `goTo()` that first awaits the saver flush (RESEARCH Pitfall 12): while waiting, the clicked control shows `loading` and the canvas stays interactive-disabled; on failure the "Changes could not be saved" modal opens.

### Top bar (48px, `#242424`, bottom border 1px `dark-4`, padding 0 16px, gap 8)
Left to right:
1. `← Images` — `Button variant="subtle" size="sm"` (14px), `aria-label` `topBar.backAria`.
2. Filename — 16px, 600, single line, ellipsis, `title` = full name, max-width 30% of the bar.
3. Status — `Badge variant="light" size="sm"` (12px) with glyph + label per Status colors table, `aria-label` = label.
4. Save indicator — 12px, see Save contract; sits right after the badge.
5. Flex spacer.
6. `Background` — `Button variant="default" size="sm"`, toggle (`aria-pressed`), icon `BackgroundIcon` 16px left of the label; `Tooltip` with `topBar.background.hint` + `Kbd G`. Disabled when the image has any box (tooltip then shows `disabledHint`).

### Tool bar (left, 48 wide, `#242424`, right border 1px `dark-4`, padding 4, `role="toolbar"` `aria-orientation="vertical"`)
- Stack gap 8, top aligned: Select (`SelectIcon`, `V`), Box (`BoxIcon`, `B`), `Divider` 24 wide, Undo (`UndoIcon`, `Mod+Z`), Redo (`RedoIcon`, `Mod+Shift+Z`).
- Buttons are `ActionIcon` 40 x 40, radius 8. Inactive tool: `variant="subtle"` gray. Active tool: `variant="filled"` accent, `aria-pressed="true"`. Undo/Redo: `variant="subtle"`, `disabled` when `pastStates` / `futureStates` is empty.
- Box is disabled when the project has no classes, when the editor is read-only (conflict, mismatch, load failure) or while an image is loading. Disabled Box shows a `Tooltip` with `tools.boxDisabled`.
- Tooltip text: "{{label}}" plus `Kbd` of the shortcut. A third slot for the future Polygon tool (Phase 6) is not rendered now.

### Canvas (center, `#141414`)
- Stage fills the center cell and resizes with it (ResizeObserver). Image drawn at natural size on a `listening={false}` layer; boxes and Transformer on a second layer; crosshair on a third layer (RESEARCH Pattern 5).
- Each image opens **fit to window** with a 24px margin: `fit = min((W-48)/imgW, (H-48)/imgH)`, capped at 4 (small images are magnified up to 400%, never beyond). Guard zero-size containers.
- Zoom: wheel zooms toward the cursor by a factor of 1.1 per notch (`Ctrl`+wheel and trackpad pinch use the same rule). Limits: min = `fit × 0.5`, max = 16 (1600%). When the scale is 3 or more the image layer sets `imageSmoothingEnabled = false` so pixels stay crisp.
- Pan: hold Space and drag with the left button, or drag with the middle button. Cursor `grab` while Space is held, `grabbing` while dragging. Space `keydown` calls `preventDefault` unless a text field has focus. Dragging past the image is allowed (no clamp) but "Fit" always recovers.
- Zoom overlay (bottom-left, 16px inset): `Paper` pill `#242424`, 1px `dark-4`, radius 8, height 32, padding 0 8px, `Group gap=4`: `−` `ActionIcon` (24 x 24 hit area inside the pill, 32 pill height), zoom percent `{{n}}%` (12px, tabular, `aria-live="off"`), `+` `ActionIcon`, `Fit` `Button variant="subtle" size="compact-xs"`. Percent is relative to natural size (`scale × 100`).
- Cursors: Select tool = default arrow, `move` over a box, resize cursors on anchors (Transformer-provided); Box tool = `crosshair` plus crosshair guides; read-only/disabled drawing = `not-allowed` only over the canvas when the Box tool was requested without classes.
- No-classes hint: when the project has zero classes a non-blocking `Paper` chip (14px, `dark-1`, `#242424`, padding 8px 16px, radius 8) with `canvas.noClassesHint` sits top-center, 16px from the top edge.
- The canvas container is focusable (`tabIndex=0`, `role="application"`, `aria-label` `canvas.aria`) and takes focus on any canvas pointer down so shortcuts work immediately. Drawing requires a pointer; keyboard users operate selection, class change, delete, undo/redo and navigation through the object list and shortcuts (documented limitation, same as other canvas annotation tools).

### Drawing, selecting, moving, resizing (D-05..D-08, D-14)
- Box tool: press and drag with the left button draws a draft (dashed, active class color). Pointer capture is mandatory so a release outside the canvas still commits (RESEARCH Pattern 5). On release the box is clamped to the image bounds; if width or height is under 4 screen px the draft is discarded silently (click or tiny drag, D-08). Otherwise the box is created with the active class, becomes selected, and is saved. The Box tool stays active. Esc cancels a draft in progress without creating anything.
- A press inside an existing box in the Box tool starts a new draft (existing boxes are non-interactive in the Box tool, RESEARCH Pitfall 7).
- Select tool: click selects (topmost box wins); click on empty canvas or Esc deselects. Dragging a selected box moves it (clamped to the image, in image coordinates); dragging a Transformer anchor resizes it (flip disabled; commit on `transformend`, then normalize/clamp, minimum size 1 image px). One move or one resize = one history entry, committed on release.
- Hover on the canvas or on an object row highlights the same box on both sides (fill 30%, stroke 3px, row `#2E2E2E`).
- Drawing a box on a background image clears the background flag in the same history entry (D-14). Any annotation change on a reviewed image demotes it to annotated in the same entry (D-15); the top bar badge updates immediately.
- Creating the 2001st box is refused: a gray notification with `canvas.limit` (`max` = 2000) and no box is created.
- Digit keys: with a box selected, digit N changes that box's class (one history entry) and leaves the active class unchanged; with nothing selected, digit N sets the active class. Digits above the number of classes do nothing. Classes beyond 9 are reachable through the panel and the dropdown only.

### Class panel (right panel, top section; `#242424`; padding 16)
- Header row: `classPanel.title` (14px, 600) with `classPanel.count` (12px, `dark-1`) right-aligned. When a box is selected, `classPanel.hintChange` (12px, `dark-1`) appears under the header (reserved 16px line so the layout does not jump).
- List: `ScrollArea`, max-height 40% of the panel and at least 120px, rows 40px: `Kbd` digit (width 24, only for the first 9 classes, empty cell otherwise) · swatch 16 x 16 · name (14px, flex 1, ellipsis, `title`) · objects of this class on this image (12px, `dark-1`, tabular, `aria-label` `classPanel.countOnImageAria`). Row is a `button` (`aria-pressed` = active class); hover `#2E2E2E`; active class has the 2px accent inset ring and `#2E2E2E`.
- Clicking a row follows D-05/D-06: nothing selected sets the active class; a selected box changes that box's class only.
- Inline create (D-07): below the list a subtle "+ Add class" button toggles a `Collapse` with the existing `AddClassForm` (same hook, validation and 409 handling as the Classes page; its input must flex to the panel width). After a class is created it becomes the active class when it is the first class of the project. With zero classes the form is open by default inside the `EmptyState` (`classPanel.empty.*`), and drawing is disabled until a class exists.
- Loading: 3 `Skeleton` rows of 40px. Error: red `Alert` (small) with the API message and "Try again"; drawing stays disabled.

### Object list (right panel, bottom section, fills the remaining height; `Divider` 1px `dark-4` above, 24px gap)
- Header: `objects.title` (14px, 600).
- Rows via `Virtuoso`, fixed height 40, in annotation order (z-order = `position`): ordinal (12px, tabular, width 16) · eye `ActionIcon` 32 (`EyeIcon` / `EyeOffIcon`, `aria-pressed`) · swatch 16 · class `Select` (size xs, flex 1, `aria-label` `objects.classAria`, searchable off, blur after change) · "×" delete `ActionIcon` 32 (`color="red" variant="subtle"`). Row click selects the box (and does not toggle on re-click); selected row has the 2px accent inset ring, hidden rows are 50% opacity.
- Background image: the list is replaced by `objects.background.body` (14px, `dark-1`) with a subtle `objects.background.clear` button.

- Loading: 3 `Skeleton` rows.

### Status, reviewed, background rules (D-13..D-15)
- Status badge is derived: reviewed (flag) > annotated (at least one box or background) > unannotated. Background shows `∅ Background`; an image that is both background and reviewed shows `✓ Reviewed` in the badge and keeps the Background button pressed.
- Mark as reviewed: toggles the flag; disabled when the image is unannotated. Pressing it on a reviewed image removes the flag (status returns to annotated).
- Background: toggles the flag; disabled while boxes exist; enabling it on an unannotated image makes it annotated.
- Next unannotated (button or `N`): awaits flush, searches after the current image in grid order, wraps, and navigates. If there is none, it stays on the image and shows a gray notification `nav.noOther` (4 s). Failure of the lookup shows a red notification with the API message.

### Save contract (D-09, D-11, D-12)
- Indicator states: **Saved** (green dot + `save.saved`), **Saving…** (Loader + `save.saving`, shown from the first unsaved edit through the debounce and the request), **Error** (red dot + `save.error`, while retrying with backoff). The three states occupy the same 96px-wide slot so the top bar does not shift.
- Accessibility: the indicator is a `role="status"` region with `aria-live="polite"` only while in Error; Saved/Saving change `aria-live="off"` so screen readers are not flooded on every gesture. Conflict is announced by its banner (`role="alert"`).
- Ctrl+S (`Mod+S`) flushes immediately and calls `preventDefault` to suppress the browser's save dialog. There is no Save button.
- Conflict (409, D-12): a red `Alert` banner (`role="alert"`, 40px tall, full width of the center column, under the top bar) with `conflict.message` and a `Reload` button (`variant="white"` on red, `size="compact-sm"`). The editor becomes read-only (tools disabled, canvas non-drawing, shortcuts for editing disabled; navigation still works) until Reload refetches the image's annotations and discards local history for that image.
- Unsaved navigation (D-11): `goTo()` waits for the flush. If the flush fails, the "Changes could not be saved" modal appears (`leave.*`): Retry re-runs the flush and then navigates; Leave anyway navigates immediately; Esc keeps the user on the image. Tab close or reload while dirty or in Error triggers the browser's `beforeunload` prompt (browser-native text, not customizable).
- Network or 5xx errors never produce toasts; the indicator carries the state. 422 errors (for example "Unknown class.") show a red notification with the API message and trigger a refetch of classes and annotations.

### Images grid integration (D-03, D-16, D-17)
- Tile click navigates to the editor with the current `sort`/`q` URL params (the P2 viewer modal is removed). Tile `aria-label` = `images:tile.aria` (filename + status).
- Status chip: `ThemeIcon variant="light"` 24 x 24, radius 4, colored and glyphed per Status colors, fills the reserved top-right slot (`pointer-events: none`), `title` and `aria-label` = status label.
- Box count: bottom-left of the thumbnail, 4px inset, a 20px-high pill (`rgba(20,20,20,0.8)` background, 12px `dark-1` text, 4px 8px padding, radius 4) with the number only; hidden at 0; `aria-label` `images:tile.boxCountAria`. It never overlaps the 24px caption strip.
- Summary row (14px, `dark-1`), directly under the title row with 8px gap: `images:summary.progress` (where `done = total − unannotated`, which counts annotated, reviewed and background) · `images:summary.reviewed`. When `unannotated = 0` and `total > 0` the sentence `images:summary.allDone` is appended. The row is hidden for an empty project and while its query has not loaded (no skeleton), and it stays hidden on summary query errors without any message.
- "Annotate next": filled `Button` in the title row's right-aligned group, left of "Upload images". Visible when the project has at least one image; disabled when `unannotated = 0`. It calls the next-unannotated endpoint without `after` and opens the editor on the result; if the result is empty (race) it shows a green notification `images:summary.allDone`. Failure shows a red notification with the API message.
- Deviation: when the project has at least one image, "Upload images" changes from `filled` to `variant="default"` so there is one primary action; with zero images it stays filled (P2 empty state).

### Accessibility
- Tool bar is `role="toolbar"`; tools are toggle buttons with `aria-pressed`; icon-only buttons carry `aria-label`s from the strings above; tooltips repeat the shortcut.
- Status is conveyed by glyph and text as well as color (four distinct glyphs).
- Class rows and object rows are focusable and operable with Enter/Space; the selected object row mirrors the canvas selection so keyboard users can select, change class (Select), toggle visibility, delete and navigate without the pointer.
- The editor is not operable by keyboard alone for drawing new boxes (pointer required); this limitation is documented here only, to keep the on-screen copy minimal.
- Modals trap focus and restore it to the trigger (Mantine default). Focus rings: Mantine default.
- Body and secondary text meet 4.5:1 against both surfaces using the `dark-1` rule in Color. Box label chips pick black or white text by luminance to stay above 4.5:1 against the class color.
- No custom animations are added; Mantine transitions only, honoring reduced motion. Canvas redraws are immediate (no tweening).

## Deviations from Phases 1-2 (for planner attention)

1. The editor route is outside `AppLayout`/`ProjectLayout`: no sidebar, no app header, full-viewport frame (D-01).
