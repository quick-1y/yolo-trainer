## Phase Goal

ROADMAP goal (verbatim): "A user can annotate images one by one with bounding boxes in a fast, keyboard-driven editor without ever losing work". This plan makes "without ever losing work" provable on the server side and closes the class-delete seam.

<objective>
Pin the Plan 01 save contract with real-app tests (validation, scoping, idempotent retry, concurrency, migration upgrade), make class deletion safe for open editors (version bump + reviewed demotion in the same transaction), and tell the user in the delete-class dialog how many objects will go with the class.

Purpose: the version + 409 contract is the costly surface later phases build on (D-12); every edge it promises must be tested before the editor grows on top of it. A user deleting a class now sees the real cost (P2 D-16).
Output: two new backend test files, extended class and migration tests, `ProjectClass.object_count`, demotion in `delete_class`, the dialog sentence.
</objective>

## Trust Boundaries

| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T3-02-01 | Tampering (integrity) | delete_class cascade | medium | mitigate | Version bump + is_reviewed demotion of affected images in the same transaction as the class delete; tested with a stale-base PUT -> 409 |
| T3-02-02 | Tampering (cross-project write) | apply_save | high | mitigate | Tests pin 404 for foreign image/project ids and 422 for a foreign class or a box id of another image (mitigation built in Plan 01) |
| T3-02-03 | Denial of Service | AnnotationSave | medium | mitigate | Tests pin NaN/Infinity, range, 2001-box and unknown-field rejections |
| T3-02-04 | Spoofing (CSRF) | PUT annotations | high | mitigate | Test pins 403 without X-Requested-With and that nothing is stored |
| T3-02-05 | Repudiation | class delete | low | accept | Single-operator tool without audit log (Phase 0 decision); the dialog states the number of objects that will be deleted |
</threat_model>
