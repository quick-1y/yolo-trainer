# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: (1) the annotation editor gains a task-type-dependent tool bar (Select, Box, Polygon, Click-to-segment), a polygon draft, polygon vertex editing, a click-to-segment point/preview/accept flow with its tool panel and its loading, latency and failure states, a box-to-polygon rule in segment projects, and a self-crossing warning in the object list; (2) the training surface gains mask metrics for segment runs: solid mask lines and dashed box lines on the mAP and precision/recall charts, `seg` in the loss chart, mask-primary Final results card, history table and quality verdict.
> Not greenfield: Mantine 9 dark theme, i18n (en/ru), the spacing/typography/color tokens, the editor frame, the chart panel anatomy and the copy tone of Phases 1-5 are reused unchanged. Everything below either reuses a P1-P5 token or is listed under "Deviations from Phases 3 and 5".

Sources: 06-CONTEXT.md D-01..D-14 (locked), 06-RESEARCH.md Patterns 1-5 and Pitfalls 1, 7, 8, 14 (measured latencies, segmenter states, captured segment metric keys, `sem_loss` finding), 03-UI-SPEC.md (editor frame, tool bar, canvas colors, object list, shortcut reference), 05-UI-SPEC.md (chart panel anatomy, series colors, Final results card, history table), installed `frontend/src` code (`ToolBar.tsx`, `icons.tsx`, `ObjectList.tsx`, `BoxShape.tsx`, `lib/shortcuts.ts`, `editorUiStore.ts`, `RunCharts.tsx`, `ChartTooltip.tsx`, `RunMetrics.tsx`, `i18n/locales/en/editor.json` and `training.json`).

No upstream design question was left open and this agent runs without a user channel, so no questions were asked during the run. Choices where CONTEXT/RESEARCH leave freedom (tool order, default tool, panel placement, point glyphs and colors, chart encoding, `sem` handling, column widths, copy) are marked "default" and listed again in "Defaults to confirm" at the end; the first three need the user's eye.

## Spacing Scale

Declared values (multiples of 4). Numeric px props (`gap={8}`, `p={16}`) as in P2-P5.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Glyph gaps, gap between a hint and its second line, legend swatch to label, `Kbd` to button label |
| sm | 8px | Gaps between controls in the tool panel, panel vertical padding, row inner gaps in the object list |
| md | 16px | Tool panel horizontal padding, panel offset from the canvas top edge, gaps between legend items, panel padding in charts |
| lg | 24px | Section gap in the editor right panel (unchanged), gap between run page blocks (unchanged) |
| xl | 32px | Sidebar/content gap, shortcut modal column gap (unchanged) |
| 2xl | 48px | Tool bar width, top bar height, empty-state vertical padding, history row height (unchanged) |
| 3xl | 64px | Empty-state hero padding (unchanged) |

Do not use Mantine's `xs` (10px), `sm` (12px) or `lg` (20px) spacing tokens or `gap="sm"` style strings in new code.

Exceptions (fixed component sizes, all multiples of 4 except borders and canvas drawing units):
- Tool options panel: top-center of the canvas, 16 from the canvas top edge, padding 8px 16px, radius 8, `max-width: min(560px, calc(100% - 32px))`, 1px `dark-4` border. Idle hint chips use the same Paper at one line (about 36 high, content-driven).
- Detail slider: 160 wide, thumb 16. Panel buttons (`Accept mask`, `Discard mask`, `Try again`): `Button size="compact-sm" h={28}` — the explicit `h={28}` overrides the Mantine `compact-sm` default height of 26 so the height is a multiple of 4. Kbd inside buttons: `size="xs"`.
- Chart column width: the three-column chart grid (`SimpleGrid cols={3} spacing={16}`, inherited unchanged from P5) is content-driven. Each column is about 309 px, derived as (960 column − 2 × 16 gap) / 3. 309 is a computed result of the grid, not a declared size, so it is not a spacing token; no element is given a fixed 309 width. The legend `min-height: 40` below is the only fixed size that depends on it.
- Tool bar gains two more 40 x 40 buttons (8 gap): Select, Box, Polygon (segment projects only), Click-to-segment, divider, Undo, Redo.
- Object list row stays 40 high. The new warning slot is 16 x 16 icon inside a 24 wide cell between the class `Select` and the delete button, 8 gap.
- Canvas drawing units (Konva), in screen pixels via `1/scale` sizing and `strokeScaleEnabled={false}`: polygon stroke 2 (3 hovered); vertex handle 10 (radius 5; radius 6 hovered); midpoint handle 8 (radius 4); first-vertex close target hit radius 8; segmentation point 16 (radius 8); draft placed vertex radius 4; minimum accepted draft size 4 screen px; duplicate-click guard 4 screen px; midpoint handles are hidden for edges shorter than 16 screen px.
- Chart legend row in segment runs: `min-height: 40` (two lines) in all three panels so plots align. Plot area stays 200 high.
- History table in segment projects: columns 8 and 9 are 112 and 128 wide (detect: 72 and 80); the inner minimum width becomes 1360 (detect: 1272).
- 1px borders and 2px focus rings are not spacing.

## Typography

Same set as P2-P5: 4 sizes and 2 weights. The editor uses only the first three sizes (as P3); the 26px tile values appear only on the unchanged Final results tiles. No new size and no new weight.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`size="md"`) | 400; 600 for run names and empty-state titles (unchanged) | 1.55 |
| Label / secondary | 14px (`size="sm"`) | 400; 600 for the tool panel state line while a request runs ("Segmenting…") and the Alert title | 1.45 |
| Caption | 12px (`size="xs"`) | 400; 600 only for the sorted column header and tooltip header (unchanged) | 1.4 (panel hints, point counter, slider label, box-metrics line, legend, axis, tooltip rows, chip text, Kbd) |
| Heading | 26px (`Title order={2}` / tile value) | 600 | 1.35 (page title and the four Final results tile values, unchanged) |

Weights: 400 and 600 only. Never `fw={500}` or `fw={700}`. Konva `Text` for the point glyphs uses `fontStyle: "normal"` at 12 px (legibility comes from the colored disc, not from weight). Numbers (point counts, metric values, epochs) use `font-variant-numeric: tabular-nums`; metric values keep three decimals.

## Color

Values are Mantine dark-scheme tokens already in effect (P2-P5). No new theme color. New colors are limited to canvas data colors (point markers, warning) and none to chrome.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#141414` (`--mantine-color-dark-9`) in the editor canvas, `#242424` (`--mantine-color-dark-7`) on training pages | Canvas matte; page body (unchanged) |
| Secondary (30%) | `#242424` (`--mantine-color-dark-7`) in the editor, `#2E2E2E` (`--mantine-color-dark-6`) on training pages | Tool bar, right panel, **the tool options panel**, chart panels, Final results card (unchanged) |
| Accent (10%) | `#1971C2` (`--mantine-primary-color-filled`) | See reserved list below |
| Destructive | `#E03131` (`--mantine-color-red-filled`) | See reserved list below |

Accent reserved for:
1. The active tool button in the tool bar (filled accent, 40 x 40, radius 8) — now one of up to four tools.
2. The 2px inset ring on the active-class row and on the selected row in the object list (unchanged).
3. Filled primary buttons: the existing "Annotate next", "Retry" (the P3 leave-dialog button `editor:leave.retry` that retries saving; a different control from the segment panel's "Try again"), "Add class", "New training", "Download .pt", "Resume training", **and the new "Accept mask" button in the click-to-segment panel (the single filled control of the editor while a preview exists)**. The segment panel's "Try again" (`common:retry`) is a `subtle` button and never uses accent.
4. Keyboard focus rings (Mantine default).

Never for: hover states, status badges, the Detail slider (it is `color="gray"`), polygon strokes or fills, vertex handles, point markers, chart series, the warning icon, links.

Destructive (red) reserved for: the "×" delete-object button, error `Alert`s (including the segment panel failure Alert), the red 422 notification, the existing red confirms. Red is never a point marker color or a chart series. This is why the "not object" point is orange, not red.

Canvas drawing colors (class color `C`; additions to the P3 table, which stays valid for boxes):

## Copywriting Contract

All strings live in the existing `editor` and `training` i18n namespaces (en/ru). No hardcoded strings. Count-bearing strings use the label form ("Points: {{count}}"; `locales.test.ts` compares flattened keys between en and ru, so no `_one/_few/_many` suffixes). Numbers via `Intl.NumberFormat(i18n.language)`. API messages (409, 422, 502, 503, 504, the raw weights error) are shown as received, in English, even in the ru UI (P1 D-05). Russian terms: «полигон» polygon, «вершина» vertex of a stored polygon, «точка» a placed point (a draft point or a segmentation point), «контур» outline, «маски» / «рамки» for masks / boxes, «сегментация по клику» click-to-segment.

## Screen and Interaction Contract

**Focal point.** The editor's primary visual anchor is the image on the `#141414` canvas matte, with the class-colored shapes on it (polygon outlines, the draft, the segmentation points and the dashed preview); the tool options panel at the top center is the secondary anchor and carries the one filled accent control (`Accept mask`) only while a preview exists. On the run page the anchor is unchanged from P5: the Final results card tiles (26px/600 values) while a run is finished, the loss and mAP charts while it runs.

### Tool bar by task type (ANNO-11, D-10, D-11)

The tool bar keeps its P3 anatomy (48 wide, `role="toolbar"`, 40 x 40 `ActionIcon`s, 8 gap, tooltip label + `Kbd` at 400 ms, active tool `variant="filled"` accent with `aria-pressed`, subtle gray otherwise). The tool set follows `project.task_type`, which the editor already loads:

| Project | Tools, top to bottom | Then |
|---------|----------------------|------|
| detect | Select (V), Box (B), Click-to-segment (S) | divider, Undo, Redo |
| segment | Select (V), Box (B), Polygon (P), Click-to-segment (S) | divider, Undo, Redo |

- Box keeps its second slot in both projects (muscle memory). In a segment project its tooltip and `aria-label` read `tools.boxToPolygon`.
- Polygon exists only in segment projects. A detect project has no polygon tool and no `P` binding (`P` does nothing there).
- Polygon, Box and Click-to-segment share one disabled rule (P3): no classes, original not decoded yet, or the editor is read-only (conflict, orientation mismatch, load failure). The disabled tooltip is `tools.boxDisabled` ("Add a class to start drawing.") or the read-only reason.
- Default tool when an image opens in a fresh editor session (default): detect = Box, segment = Polygon. The tool is kept across images (P3). If the kept tool does not exist for the project, the project default applies.
- Switching tool cancels an unfinished polygon draft or a segmentation preview without asking (nothing unaccepted is saved). It does not touch the saved set or the undo history.

### Tool options panel (new, canvas overlay)

One `Paper` overlay (`#242424`, 1px `dark-4`, radius 8, padding 8px 16px, `max-width: min(560px, calc(100% - 32px))`) at the top center of the canvas, 16 from the canvas top edge. It is the single place for tool instructions, tool state and the segmentation controls. It lives in the same slot as the P3 "no classes" chip; the chip wins when the project has zero classes. Pointer events on the panel are stopped (a click on the panel never reaches the stage). The panel never overlaps the 40px conflict banner (the banner is above the canvas).

| Active tool and state | Panel content |
|-----------------------|---------------|
| Select, nothing selected | panel hidden |
| Select, a polygon selected | one 12px `dark-1` line `polygon.hint.selected` |
| Box, detect project | panel hidden |
| Box, segment project | one 12px `dark-1` line `box.hint.segment` |
| Polygon, no points | one 12px `dark-1` line `polygon.hint.start` |
| Polygon, 1-2 points | `polygon.hint.few` |
| Polygon, 3 or more points | `polygon.hint.drawing` |
| Click-to-segment | the segmentation panel (below) |

The status lines inside the panel are one polite live region (`role="status"`, `aria-live="polite"`) that announces state changes only (preparing, segmenting, empty result, errors), never point counts.

### Polygon tool (ANNO-04, D-01, D-03, D-04)

- **Placing points.** Click with the left button adds a vertex at the pointer, clamped to the image bounds (a click outside the image places the point on the nearest edge). A click within 4 screen px of the previous point is ignored (guards double-click, which never closes a polygon). The rubber band follows the pointer; crosshair guides show.
- **Close.** Click the first vertex (hit radius 8 screen px, highlighted on hover only once 3 or more points exist) or press Enter, both only with 3 or more points. With fewer than 3 points, Enter and the first-vertex click do nothing; the panel line says why (`polygon.hint.few`). A close creates one polygon with the active class, which becomes the last row of the object list (scrolled into view), is saved, and adds exactly one history entry. The Polygon tool stays active. A polygon whose bounding box is under 4 screen px in width or height at close is discarded silently (the same rule as a tiny box, P3 D-08).
- **Cancel and undo while drawing.** Esc cancels the whole draft. Backspace removes the last placed point (and cancels the draft when it was the only one). Neither touches the history. Pan and zoom never cancel a draft; a tool or image change does.
- **Limits.** 1000 points per polygon, 20000 per image, 2000 objects per image (P3 `canvas.limit`). The point that would exceed a limit is not placed; a gray notification shows `canvas.pointLimit`, `canvas.pointsTotalLimit` or `canvas.limit`.
- **Self-crossing contours are allowed** and saved as drawn (D-03). Nothing is blocked while drawing or editing; the only signal is the warning icon in the object list.
- Existing shapes are non-interactive while the Polygon tool is active (the P3 Pitfall 7 rule, as for the Box tool): a press always places a point.

### Polygon selection and vertex editing (ANNO-04, D-02)

All of it happens in the Select tool, on the selected polygon.

- **Select.** Click inside the polygon (its fill listens) or on its outline selects it; the topmost shape wins; click on empty canvas or Esc deselects. A selected polygon shows vertex handles and midpoint handles. Hover highlights the same shape on the canvas and in its object-list row (fill 30%, stroke 3px, row `#2E2E2E`), as for boxes.
- **Move a vertex.** Drag a vertex handle. The point stays inside the image. One drag is one history entry, committed on release.
- **Add a vertex.** Drag a faded midpoint handle. On drag start the new vertex is inserted at the edge midpoint and the same drag moves it, so adding and placing is one gesture and one history entry.
- **Delete a vertex.** Alt+click or right-click on a vertex handle (the browser context menu is suppressed over handles and in the Polygon and Click-to-segment tools). A polygon never drops below 3 vertices: the 4th deletion attempt shows the gray notification `canvas.minVertices` (min = 3) and changes nothing. One deletion is one history entry.
- **Move the whole polygon.** Drag the shape body. The translation is clamped so that every vertex stays inside the image. One drag is one history entry.
- **Change the class.** The same as for boxes: digit keys with the polygon selected, the class panel, or the row's class `Select` (one history entry; the active class is unchanged by the digit).
- **Delete the polygon.** Delete or Backspace, or the row's "×" (no confirmation; Ctrl+Z restores it).
- While a pan can start (Space held or middle button), handles and shapes go inert (as boxes).
- A polygon in a reviewed image demotes it to annotated in the same history entry (P3 D-15). Drawing on a background image clears the background flag in the same entry (P3 D-14).

### Box tool in a segment project (D-11)

The draft rectangle, crosshair guides, clamping and the 4-screen-px minimum are exactly those of P3. On release the box is not stored as a box: one polygon is created with 4 vertices in the order top-left, top-right, bottom-right, bottom-left (the winding the server already writes into labels), with the active class. It appears as an ordinary polygon, is saved and is one history entry. The conversion feedback is the persistent panel line `box.hint.segment`, the tool tooltip `tools.boxToPolygon`, and the result itself (a polygon row in the object list); there is no toast. The user can switch to Select and drag the four vertices at once. Boxes never exist in a segment project's editor state.

### Click-to-segment tool (ANNO-05, D-05..D-08, D-10)

Interaction (the Roboflow Smart Polygon pattern):

1. **Select the tool** (S or the tool bar). The editor asks the api to prepare the segmentation service (idempotent) and, once ready, to encode the current image in the background, so the first click is fast. While this happens the panel shows the matching state line.
2. **Click on the object** adds an "object" point (green disc with `+`). **Shift+click or right-click** adds a "not object" point (orange disc with `−`). The point marker appears immediately at the click. At most 20 points per object; the 21st is refused with the panel line `segment.pointLimit`.
3. **Live preview.** After each point the preview is recomputed (see Latency and states). In a segment project the preview is the simplified polygon (dashed outline, fill 30%); in a detect project it is the mask's bounding box (dashed rectangle) with the mask outline as a thin white line.
4. **Accept** with Enter or the `Accept mask` button: the preview becomes an ordinary object with the active class. Segment project: a polygon simplified at the current Detail value. Detect project: a box from the mask's bounding box. It is selected in the object list and scrolled into view, saved, and one history entry. The points and the preview clear, and the tool stays active for the next object.
5. **Discard** with Esc or the `Discard mask` button, or Backspace to remove only the last point (the preview recomputes; with no points left the preview clears). Changing tool or image clears everything. A preview is never autosaved.

Existing shapes are non-interactive while this tool is active (a click always adds a point). Zoom, pan and fit work as always. Digit keys still change the active class, which only affects the Accept mask result.

**Segmentation panel** (inside the tool options panel; `Stack gap={8}`):

| Row | Content |
|-----|---------|
| 1. State line (14px; 12px `dark-1` for hints) | one of the states below, with a 12px `Loader` for the in-progress ones |
| 2. Training note (12px `dark-1`) | `segment.trainingNote`, shown only while the existing `/training/active` query reports an active run (D-07). Informational, non-blocking; the tool works regardless |
| 3. Controls (only while a preview exists) | `Group gap={16}`: `segment.detail` label (12px `dark-1`) + Detail `Slider` (160 wide) + `segment.vertices` count (12px, tabular); right-aligned `Group gap={8}`: `Discard mask` (`variant="default"`, `size="compact-sm"`, `h={28}`, `Kbd Esc`) and `Accept mask` (filled accent, `size="compact-sm"`, `h={28}`, `Kbd Enter`) |

The Detail slider is shown in segment projects only (a detect project's box does not depend on detail). It spans 0 to 100, higher = more points, and maps to a closed-contour Ramer-Douglas-Peucker tolerance of `0.006 × (0.0005 / 0.006)^(value / 100)` times the contour perimeter (06-RESEARCH.md Pattern 3). The default value is 55 (tolerance about 0.0015 × perimeter, which lands near 20-60 vertices on typical masks). Moving it recomputes the preview locally from the cached dense contour with no request, updates the point count live, and never adds a history entry. The chosen value is remembered for the rest of the session. If simplification would leave fewer than 3 vertices, the result falls back to the 4 corners of the contour's bounding box. The Accept button and Enter are disabled while no preview exists or the editor is read-only.

**States and latency** (measured on the dev machine: first encode 1.3-1.6 s, each further point about 0.1 s, up to about 3.4-5.6 s on the first click while a CPU training run saturates the machine):

| State | What the user sees | Notes |
|-------|--------------------|-------|

| Preparing the image | `segment.state.preparing` with a Loader (12px `dark-1`), tool already usable | Background encode after selecting the tool or opening an image; a click during it simply waits for it |
| Ready, no points | `segment.hint.idle` | |
| Request in flight | The new point is already drawn. State line `segment.state.working` (14px/600) with a Loader; the previous preview, if any, drops to 50% | One request at a time; points added meanwhile are sent as one request after the response; a response for outdated points is ignored (the latest wins) |
| Request in flight longer than 5 s | `segment.state.slow` is appended as a second 12px `dark-1` line | |
| Preview ready | Preview on the canvas, controls row visible, state line `segment.hint.refine` | |

| Point limit | `segment.pointLimit` for as long as the user keeps clicking; cleared by the next accepted point removal | |

### Server geometry rules and errors (ANNO-11, D-09, D-12)

- The tool set already prevents wrong geometry, so the UI path to a refusal is a stale editor, an old tab, or a direct API call. A refused save (422) follows the P3 rule: a red notification with the API message as received, then classes and annotations are refetched, and the editor shows the server's set. No new dialog.
- After the one-time migration (D-09) a segment project holds only polygons: boxes that were stored earlier simply render as 4-vertex polygons. A tab that was open during the upgrade gets the P3 conflict banner on its next save (409), because the migration bumps each touched image's `annotation_version`; "Reload" refetches the set.
- The 2000-object cap (P3) counts boxes and polygons together; the 1000 and 20000 point caps (above) keep a full save under the 1 MiB nginx limit.

### Object list changes (ObjectList, D-03)

- Rows are unchanged for boxes. Polygon rows are the same 40px row: ordinal · eye · swatch · class `Select` · **warning cell** · "×". The warning cell (24 wide, 16 x 16 `WarningIcon` in `yellow-5`) renders only when the polygon crosses itself, is `role="img"` with `aria-label` and `title` = `objects.selfIntersect` (a `title`, not a `Tooltip`, honoring the P3 rule of no tooltip per row), and does not change the row's selection or hover behavior. Rows without the warning keep an empty 24px cell so the `Select` width does not jump while editing.
- Self-intersection is evaluated on demand for visible rows and memoized by the polygon's points identity; it is never computed in the store on every drag tick.
- A row click selects the object and switches to the Select tool (P3). Hide, class change and delete behave as for boxes. The header `Objects: N` counts all objects.
- Empty state: `objects.empty.*` with the body chosen by task type (above). Background image state and loading skeletons are unchanged.

The `?` modal is generated from `lib/shortcuts.ts` (unchanged mechanism) and gains a seventh group, **Polygons and segmentation** (`shortcuts.group.shapes`), plus two rows in Tools. Two-column grid, column gap 32, row gap 16, scrolling in the existing `ScrollArea`.

### Training: charts for segment runs (success criterion 4, D-13)

### Accessibility

## Deviations from Phases 3 and 5 (for planner attention)

1. The Phase 3 rule "neither the editor nor the API looks at the project's task type (D-18)" is reversed: the tool bar, the default tool, the object-list copy and the server all follow the task type. The stale comment in `EditorPage.tsx` must be replaced.
2. The tool bar grows from two tools to three or four. Box keeps its slot; Polygon and Click-to-segment are added; the P3 note "a third slot for the future Polygon tool is not rendered now" is now fulfilled.
3. A new canvas overlay, the tool options panel, is added at the top center of the canvas. It shares the slot of the P3 "no classes" chip.
4. Accent gains one reserved use: the filled "Accept mask" button of the segment panel. The Detail slider deliberately does not use accent.
5. Three inline SVG icons are added (`PolygonIcon`, `SegmentIcon`, `WarningIcon`); the "no new inline SVGs" rule belonged to Phase 5 only.
6. Two canvas data colors are added for segmentation points (Mantine green-5 `#51CF66` and orange-5 `#FF922B`), outside the 60/30/10 table like the P3 class-derived colors. Orange, not red, marks "not object" because red is reserved for destructive and error states.
7. The object list gains a warning cell (24 wide) in polygon rows.
8. The shortcut reference gains a seventh group and about 12 rows; several P3 strings change from "box" to "object" wording.
9. Charts: in segment runs dashed means "box metrics" on the mAP and precision/recall charts, whereas in detect runs and on the loss chart dashed keeps its P5 meaning (second metric, or Validation). Both are labeled in the legend, so dash is never the only signal.
10. The Final results card loses the `metrics.maskNote` line and gains a box-metrics line; the history table is wider for segment projects.

## Defaults to confirm (chosen by this spec; the first three need the user's eye)

1. `sem` loss is excluded from the Train and Validation loss sums and from the tooltip grid for segment runs, with an explanatory caption (06-RESEARCH.md Open Question 1).
2. Segment-run chart encoding: color = metric, solid = mask, dashed = box, with "(masks)" and "(boxes)" in the legend (06-RESEARCH.md Open Question 2).
3. The not-object point is orange with a minus glyph (red stays reserved for errors), and the positive point is green with a plus.
4. Tool order: Select, Box, Polygon, Click-to-segment; default tool is Box in detect projects and Polygon in segment projects.
5. Keys: P polygon, S click-to-segment, Enter close/accept; Backspace also removes the last segmentation point.
6. The Detail slider default is 55 (tolerance about 0.0015 × perimeter) and its value is remembered for the session; it is hidden in detect projects.
7. The tool options panel sits at the top center of the canvas and is the only place for tool hints, tool state and the segmentation controls.
8. Limits: 20 segmentation points per object; 1000 points per polygon; 20000 per image.
9. The self-crossing warning is only an icon in the object list (no canvas marker).
10. Segment-project history columns widen (112 / 128, minimum width 1360) instead of abbreviating "(masks)".
