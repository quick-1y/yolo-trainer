## Scope note (tracer split)

The phase tracer is the path "click vertices on the canvas -> store -> autosave PUT -> SQLite row -> GET -> rendered polygon". Carried by one plan it needs at least 17 files (7 backend, 10 frontend), above the 15-file plan budget, so it is split at the wire contract into two consecutive halves of the same path: this plan is the **server half** (migration -> model -> schema -> service -> HTTP route, proven by a real TestClient PUT/GET round trip, with no stubbed tier), and Plan 06-14 (Wave 2) is the **browser half** (GET -> api types -> store -> canvas, and store -> autosave PUT), built against this plan's real schemas. The Polygon tool that lets a user draw is Plan 06-15. 7 files; token estimate 75000 (uncalibrated, confidence low).

<assumption_delta_decision>
Primary noun: the annotation object row in `annotations` (kind box | polygon). Decision: add-alongside. A polygon adds a nullable `points` column next to x/y/w/h; for a polygon row x/y/w/h become a derived bounding box (cheap queries, Phase 8 IoU, trivial downgrade). Accepted debt: two geometry representations in one table. A later promote would be forced only if a third geometry kind (oriented boxes, keypoints) arrived.
</assumption_delta_decision>
