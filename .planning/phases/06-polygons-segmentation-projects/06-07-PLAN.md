## Phase Goal

ROADMAP goal (verbatim, not in user-story form): "A user can annotate `segment` projects with polygons, drawn by hand or generated with one click, and train segmentation models end-to-end". No story is invented; run `/gsd-mvp-phase 6` if one is wanted.

## Slice note

This plan is the click-to-segment stream's own end-to-end slice through every server tier (worker child process -> HTTP -> api route) and stops at the public API, which is what the browser tool of Plan 06-08 calls; after it, any API client (and the compose smoke test of Plan 06-13) can segment an image. Task 1 wires the thin path with an injectable engine, Task 2 fills in the real MobileSAM engine behind the same seam (a stub that is later filled without an architectural change). It runs in Wave 1 next to the polygon tracer because it shares no file with it. Token estimate 150000 (uncalibrated, confidence low) is above the 100000 smart-zone budget; if a split is wanted, Task 1 / Task 2 is the seam.

<objective>
A click-to-segment request goes from the api to a long-lived MobileSAM process in the worker container and comes back as a dense, normalized object contour within seconds, while training keeps running untouched.

Purpose: ANNO-05's server side, D-06 (one fixed lightweight SAM chosen for CPU latency, measured: about 1.3-1.6 s first encode, about 0.1 s per further point), D-07 (outside the training queue). The api stays torch-free (P1 D-17).
Output: the segmenter package (app, engine, contour), `SegmenterHost`, worker settings, api client and routes, settings, compose wiring, tests.
</objective>
