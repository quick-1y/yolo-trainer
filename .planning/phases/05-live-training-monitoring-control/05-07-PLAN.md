## Phase Goal

ROADMAP goal (verbatim, not in user-story form): "A user can watch training progress live, stop or resume runs, understand failures, and browse the history of all runs". No user story is invented (run `/gsd-mvp-phase 5` for one).

<objective>
Resuming behaves predictably everywhere: times count only active training, the user always sees whether and from which epoch a run can be resumed (or why not), a resumed run waiting in the queue can be taken back without losing its progress, and the settings card records how often a run was resumed.

Purpose: completes D-09 (active-time duration), D-10 (gated, explained Resume), D-11 (device re-check, same settings) and the queued-resume semantics (Open Question 1) on top of Plan 05-06; the duration feeds the history table (TRAN-08).
Output: active-time accounting in the supervisor and restart sweeps, `active_seconds`/`segment_started_at`/`resume_blocked` in the read model, device check and "Cancel resume" in the api, `runActiveSeconds`, run page resume lines and states, settings row, i18n.
</objective>
