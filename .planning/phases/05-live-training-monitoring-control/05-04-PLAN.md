<objective>
A failing run (out of memory, invalid dataset, no network for weights, full disk, killed process) ends in a failed state whose page explains the cause in the user's language with a concrete next step, while the raw message and log stay available.

Purpose: TRAN-11 / D-16 and success criterion 5. The category codes become a contract between the worker, the DB and the i18n catalog (costly to reverse), so the code set and the allow-list are fixed here. Per D-17 this phase adds only clear failure reporting: no pre-start checks (no disk-space warning, no CPU batch warning) are added to the start form or the api.
Output: migration 0006, `yolo_trainer_common/failures.py` with fixture tests, category in error.json and in the supervisor's failure writes, `error_category` in the read model and the stream, `FailureAlert`, i18n for seven codes.
</objective>
