## Phase Goal

ROADMAP goal (verbatim, not in user-story form): "A user can watch training progress live, stop or resume runs, understand failures, and browse the history of all runs". No user story is invented (run `/gsd-mvp-phase 5` for one).

<objective>
A user cancels a running training job from its page; within seconds the run is cancelled, its process is gone, and the next queued run starts.

Purpose: TRAN-06, D-06..D-08, success criterion 2. Control flows only through the database (the api cannot signal the worker's PID); the supervisor stays the single writer of run state.
Output: migration 0007, `cancel_run` + POST route, supervisor cancel branch + `mark_cancelled`, restart sweeps honoring the flag, `cancelling` in the read model and the stream, `CancelRunModal`, the "Cancelling…" UI, README note on native Windows.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> api (POST cancel) | state-changing request with integer ids |
| api -> DB -> worker supervisor | the cancel flag crosses the container boundary through the database |
| worker supervisor -> OS processes | process-group signals |
